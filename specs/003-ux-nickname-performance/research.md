# Research: 003 이름 입력/수정 · 응답 속도

## 1. 인증 방식 (T021)

- 운영(서울) 프로젝트의 JWKS(`/auth/v1/.well-known/jwks.json`)에 `ES256` 공개키가 있다 → JWT 서명 키가 **비대칭**이다.
- 따라서 `supabase.auth.getClaims()`로 서버 왕복 없이 로컬 검증이 가능하다. 만료된 토큰만 갱신을 위해 서버를 호출한다.
- **Decision**: 미들웨어의 `getUser()`를 `getClaims()`로 교체. 서버 액션 등 쓰기 경로의 `getUser()`는 그대로 둔다(권한은 DB가 강제).

## 2. 요청당 호출 수 (T023)

| 단계 | 변경 전 | 변경 후 |
|---|---|---|
| 미들웨어 인증 | `auth.getUser()` 서버 왕복 1회 | `getClaims()` 로컬 검증(0회) |
| 미들웨어 회원 조회 | `members` 1회 | `members` 1회 (유지) |
| 레이아웃 인증 | `auth.getUser()` 1회 | 0회 (헤더 사용) |
| 레이아웃 회원 조회 | `members` 1회 | 0회 (헤더 사용) |
| 합계(인증+회원) | 4회 | 1회 |

- 미들웨어가 계산한 회원 정보를 요청 헤더(`x-member-*`)로 넘기며, 클라이언트가 보낸 같은 헤더는 먼저 제거한다(`stripMemberHeaders`). 헤더는 표시용이고 권한은 DB(RLS·RPC)가 강제한다.
- 앞선 지연의 주원인은 **지역 불일치**(Vercel 미국 동부 ↔ Supabase 인도)였고, 서울 이전(`icn1` + `ap-northeast-2`)으로 해소됐다. 위 변경은 남은 중복 왕복을 줄인다.

## 3. 기준값 측정 (T020, T026) — 미완

- 인증된 화면이라 비로그인 `curl`로 측정할 수 없다. 사용자의 로그인 세션에서 측정해야 한다.
- 방법: 브라우저 개발자 도구 Network 탭에서 `notices`, `rounds?kind=screen`, `rounds/[id]` 문서 요청의 TTFB를 각 10회 기록(캐시 비활성), 그리고 등록/투표 버튼 클릭부터 화면 전환까지 시간.
- 측정값은 이 표에 기록한다.

## 4. 서버 액션 리다이렉트 (T016 중 발견)

- 서버 액션이 `redirect("/")` 하면 미들웨어가 다시 `/pending`으로 보내는데, 이 경우 주소창이 `/`로 남고 내용만 승인 대기 화면이 되었다(E2E에서 확인).
- **Decision**: 액션이 가입 상태를 알고 있으면 최종 목적지로 직접 이동한다(`set_my_nickname`이 상태를 반환).
