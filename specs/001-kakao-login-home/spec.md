# Feature Specification: 카카오 로그인 · 홈 화면 추가 안내 · 홈 대시보드

**Feature Branch**: `001-kakao-login-home`

**Created**: 2026-10-26

**Status**: Draft (개정 2026-10-27: 홈 대시보드 폐기·닉네임 입력 — 003 참고)

**Input**: User description: "스크린골프와 필드모임을 운영하는 소모임 회원들이 함께 쓰는 모바일 우선 웹앱(PWA). 첫 기능: 카카오 로그인, '홈 화면에 추가' 안내 팝업, 홈 대시보드(가장 가까운 라운딩 일정과 현재 모임 공지사항이 한눈에 보임). 디자인(피그마) 없음 - 모바일 우선 기본 레이아웃. 한국어 UI. 무료 배포."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 카카오 계정으로 로그인 (Priority: P1)

모임 회원이 별도 회원가입 없이 카카오 계정으로 로그인하여 앱을 사용한다. 로그인하지 않은 방문자는 로그인 화면만 볼 수 있다.

**Why this priority**: 모든 기능의 전제이며, 멤버와 매니저를 구분하기 위한 기반이다.

**Independent Test**: 로그인 화면에서 카카오 로그인을 완료하면 홈 화면으로 이동하고, 로그아웃하면 다시 로그인 화면으로 돌아오는지로 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 방문자, **When** 앱의 어느 화면 주소로 접근해도, **Then** 로그인 화면으로 이동한다.
2. **Given** 로그인 화면, **When** 카카오 로그인을 완료하면, **Then** 홈 화면이 표시되고 내 닉네임이 보인다.
3. **Given** 로그인한 회원, **When** 앱을 닫았다가 다시 열면, **Then** 다시 로그인하지 않고 홈 화면이 표시된다.
4. **Given** 로그인한 회원, **When** 로그아웃하면, **Then** 로그인 화면으로 이동하고 보호된 화면에 접근할 수 없다.
5. **Given** 카카오 인증 화면, **When** 사용자가 동의를 취소하거나 인증이 실패하면, **Then** 로그인 화면에 한국어 안내 메시지가 표시되고 다시 시도할 수 있다.

---

### User Story 1-B - 가입 승인 (Priority: P1)

카카오로 처음 로그인한 사용자는 승인 대기 상태가 되고, 매니저가 승인해야 모임 정보를 볼 수 있다.

**Why this priority**: 외부인에게 모임 정보가 노출되지 않도록 하는 접근 통제의 핵심이다.

**Independent Test**: 새 계정으로 로그인하면 승인 대기 화면만 보이고, 매니저가 승인하면 홈이 보이는지로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 처음 로그인한 사용자(최초 가입자 제외), **When** 로그인이 끝나면, **Then** 승인 대기 안내 화면만 표시되고 홈·공지 등은 접근할 수 없다.
2. **Given** 승인 대기 중인 신청이 있을 때, **When** 매니저가 가입 신청 목록을 열어 승인하면, **Then** 해당 사용자는 다음 접속(또는 새로고침)부터 홈을 볼 수 있다.
3. **Given** 승인 대기 중인 신청, **When** 매니저가 거절하면, **Then** 해당 사용자는 거절 안내 화면만 볼 수 있다.
4. **Given** 멤버 또는 승인 대기 사용자, **When** 가입 신청 목록 조회나 승인을 시도하면, **Then** 거부된다.
5. **Given** 서비스에 회원이 한 명도 없을 때, **When** 첫 사용자가 로그인하면, **Then** 승인 없이 매니저가 되어 홈으로 이동한다.

### User Story 2 - 홈 대시보드에서 다음 라운딩과 공지 확인 (Priority: P1)

로그인한 회원이 홈 화면에서 가장 가까운 라운딩 일정과 현재 모임 공지사항을 스크롤 없이 한눈에 확인한다.

**Why this priority**: 회원이 앱을 여는 가장 큰 이유이며, 앱의 핵심 가치를 전달한다.

**Independent Test**: 라운딩 일정과 공지를 준비해 두고 홈 화면을 열어 두 정보가 모두 표시되는지, 데이터가 없을 때 빈 상태 안내가 나오는지로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 오늘 이후 예정된 라운딩이 여러 개 있을 때, **When** 홈을 열면, **Then** 시작 시각이 현재와 가장 가까운 미래 라운딩 1건이 종류(스크린/필드), 일시, 장소, 비용과 함께 표시된다.
2. **Given** 예정된 라운딩이 없을 때, **When** 홈을 열면, **Then** "예정된 라운딩이 없습니다" 안내가 표시된다.
3. **Given** 이미 지난 라운딩만 있을 때, **When** 홈을 열면, **Then** 지난 라운딩은 표시되지 않고 빈 상태 안내가 표시된다.
4. **Given** 공지사항이 등록되어 있을 때, **When** 홈을 열면, **Then** 최신 공지의 제목과 내용 요약이 표시된다.
5. **Given** 공지사항이 없을 때, **When** 홈을 열면, **Then** "등록된 공지가 없습니다" 안내가 표시된다.
6. **Given** 휴대폰 화면 폭(약 360px), **When** 홈을 열면, **Then** 가로 스크롤 없이 두 정보 영역이 모두 보인다.

### User Story 3 - 매니저가 공지사항 등록·수정 (Priority: P2)

매니저가 모임 공지사항을 등록하고 수정·삭제하여 회원들이 홈에서 확인하게 한다. 일반 멤버는 공지를 읽기만 할 수 있다.

**Why this priority**: 홈 대시보드에 보여줄 공지를 채우는 최소한의 수단이며, 매니저/멤버 권한 구분의 첫 적용 사례다. 라운딩 일정 등록은 별도 기능(후속 스펙)이다.

**Independent Test**: 매니저 계정으로 공지를 등록하면 멤버 계정의 홈에 즉시 표시되고, 멤버 계정은 등록·수정·삭제 수단이 없고 시도해도 거부되는지로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 매니저로 로그인, **When** 제목과 내용을 입력해 공지를 등록하면, **Then** 모든 회원의 홈에 해당 공지가 최신 공지로 표시된다.
2. **Given** 등록된 공지, **When** 매니저가 수정하거나 삭제하면, **Then** 홈에 변경 내용이 반영된다.
3. **Given** 일반 멤버로 로그인, **When** 홈과 공지 화면을 보면, **Then** 등록·수정·삭제 버튼이 보이지 않고, 직접 요청해도 거부된다.
4. **Given** 공지 등록 화면, **When** 제목 또는 내용을 비워 저장하면, **Then** 저장되지 않고 입력 오류 안내가 표시된다.

---

### User Story 4 - '홈 화면에 추가' 안내 팝업 (Priority: P2)

앱을 브라우저에서 처음 연 회원에게 홈 화면에 추가하는 방법을 안내하는 팝업을 보여 주어, 앱처럼 빠르게 열 수 있게 한다.

**Why this priority**: 회원의 재방문률을 높이지만, 없어도 핵심 기능은 동작한다.

**Independent Test**: 브라우저(미설치 상태)에서 앱을 열었을 때 팝업이 나오고, 닫은 뒤에는 일정 기간 다시 나오지 않으며, 홈 화면 앱으로 실행하면 나오지 않는지로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 홈 화면에 추가하지 않고 브라우저로 접속한 로그인 회원, **When** 홈이 열리면, **Then** 홈 화면 추가 안내 팝업이 표시된다.
2. **Given** iOS 기기, **When** 팝업이 표시되면, **Then** 공유 버튼 → "홈 화면에 추가" 순서의 수동 안내가 표시된다.
3. **Given** 안드로이드 기기에서 바로 설치가 지원될 때, **When** 팝업이 표시되면, **Then** "추가하기" 버튼으로 설치를 진행할 수 있다.
4. **Given** 팝업이 표시된 상태, **When** 회원이 닫기를 선택하면, **Then** 이후 7일 동안 다시 표시되지 않는다.
5. **Given** 홈 화면에 추가된 앱으로 실행한 경우, **When** 홈이 열리면, **Then** 팝업이 표시되지 않는다.
6. **Given** 팝업에서 "다시 보지 않기"를 선택하면, **When** 이후 접속하면, **Then** 팝업이 다시 표시되지 않는다.

---

### Edge Cases

- 카카오 계정에서 닉네임 또는 프로필 이미지 제공에 동의하지 않은 경우: 기본 이미지로 대체해 로그인을 진행하되, 닉네임이 없으면 이름 입력 화면에서 이름을 입력해야 앱을 쓸 수 있다(개정 2026-10-27, 003 US4)한다.
- 같은 카카오 계정으로 다른 기기에서 로그인: 동일한 회원으로 인식한다.
- 네트워크 오류로 홈 데이터를 불러오지 못한 경우: 오류 안내와 "다시 시도" 버튼을 표시한다.
- 라운딩 시작 시각이 정확히 현재 시각인 경우: 아직 시작 전이 아닌 것으로 보아 "가장 가까운 라운딩"에서 제외한다.
- 시작 시각이 같은 라운딩이 둘 이상인 경우: 먼저 등록된 라운딩을 표시한다.
- 공지가 매우 긴 경우: 홈에서는 요약(말줄임)으로 표시하고 상세 화면에서 전체를 보여 준다.
- 여러 공지가 있는 경우: 홈에는 최신 1건을 표시한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 카카오 계정 로그인만을 인증 수단으로 제공해야 한다.
- **FR-002**: 로그인하지 않은 사용자는 로그인 화면 외의 모든 화면에 접근할 수 없어야 한다.
- **FR-003**: 시스템은 로그인 후 재방문 시 로그인 상태를 유지하고, 회원이 로그아웃할 수 있어야 한다.
- **FR-004**: 시스템은 회원 정보로 카카오 닉네임(없으면 회원이 직접 입력한 이름)과 프로필 이미지만 저장해야 하며, 그 외 개인정보는 수집하지 않아야 한다. *(개정 2026-10-27, 003 FR-009~FR-014)*
- **FR-005**: 시스템은 회원을 "매니저"와 "멤버" 두 역할로 구분해야 한다.
- **FR-006**: 홈 화면은 시작 시각이 현재 이후이면서 가장 가까운 라운딩 1건(종류, 일시, 장소, 비용)을 표시해야 한다.
- **FR-007**: 홈 화면은 최신 공지 1건의 제목과 내용 요약을 표시해야 하며, 공지를 눌러 전체 내용을 볼 수 있어야 한다.
- **FR-008**: 예정된 라운딩 또는 공지가 없을 때 각각 한국어 빈 상태 안내를 표시해야 한다.
- **FR-009**: 매니저는 공지를 등록·수정·삭제할 수 있어야 하며, 제목과 내용은 필수 입력이다.
- **FR-010**: 멤버는 공지를 읽기만 할 수 있어야 하며, 쓰기 시도는 화면 노출 여부와 관계없이 거부되어야 한다.
- **FR-011**: 홈 화면에 추가하지 않은 상태로 접속한 회원에게 홈 화면 추가 안내 팝업을 표시해야 하며, iOS와 안드로이드에 맞는 안내를 제공해야 한다.
- **FR-012**: 팝업은 닫기 후 7일간 재표시하지 않고, "다시 보지 않기" 선택 시 재표시하지 않으며, 홈 화면 앱으로 실행 중일 때는 표시하지 않아야 한다.
- **FR-013**: 모든 화면과 메시지는 한국어로 제공하고, 휴대폰 화면 폭(360px 이상)에서 가로 스크롤 없이 사용할 수 있어야 한다.
- **FR-014**: 로그인 실패, 데이터 불러오기 실패, 입력 오류 시 사용자에게 한국어 안내를 표시하고 재시도할 수 있어야 한다.
- **FR-015**: 카카오 로그인 후 처음 접속한 사용자는 "승인 대기" 상태가 되며, 매니저가 승인하기 전에는 홈·공지·라운딩 등 모임 정보를 볼 수 없고 승인 대기 안내 화면만 볼 수 있어야 한다. (최초 가입자는 자동으로 매니저가 되며 승인 절차를 거치지 않는다.)
- **FR-016**: 매니저는 승인 대기 중인 가입 신청 목록(닉네임, 신청 시각)을 보고 각 신청을 승인하거나 거절할 수 있어야 한다. 거절된 사용자는 모임 정보를 볼 수 없으며 거절 안내 화면을 본다.
- **FR-017**: 가입 승인·거절 권한은 매니저에게만 있어야 하며, 멤버나 승인 대기 사용자의 시도는 거부되어야 한다.

### Key Entities *(include if feature involves data)*

- **회원(Member)**: 카카오 계정과 1:1로 대응하는 모임 구성원. 닉네임, 프로필 이미지, 역할(매니저/멤버), 가입 상태(승인 대기/승인/거절), 가입 시각을 가진다.
- **공지(Notice)**: 매니저가 작성하는 모임 공지. 제목, 내용, 작성자(회원), 작성·수정 시각을 가진다.
- **라운딩(Round)**: 스크린골프 또는 필드 모임 일정. 종류, 시작 일시, 장소, 비용을 가진다. 이 기능에서는 홈에서 읽어 표시하는 대상이며, 등록·수정은 후속 기능에서 다룬다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 방문한 회원이 로그인 화면에서 홈 화면 도달까지 30초 이내에 완료할 수 있다.
- **SC-002**: 로그인한 회원은 홈 화면을 연 뒤 3초 이내에 다음 라운딩과 최신 공지를 모두 확인할 수 있다.
- **SC-003**: 로그인하지 않은 사용자가 보호된 화면의 정보를 볼 수 있는 경우가 0건이다.
- **SC-008**: 승인되지 않은 사용자(대기·거절)가 모임 정보를 볼 수 있는 경우가 0건이다.
- **SC-004**: 멤버 역할 계정이 공지를 등록·수정·삭제하는 데 성공하는 경우가 0건이다.
- **SC-005**: 홈 화면 추가 안내 팝업은 미설치 기기에서 첫 접속 시 100% 표시되고, 닫기 선택 후 7일 이내 재표시는 0건이다.
- **SC-006**: 휴대폰 화면 폭 360px에서 홈 화면의 가로 스크롤이 발생하지 않는다.
- **SC-007**: 매니저가 공지를 등록하면 1분 이내에 모든 회원의 홈에 반영된다.

## Assumptions

- 대상 사용자는 한국어를 쓰고 카카오톡 계정을 보유한 소규모(수십 명 이하) 모임 회원이다.
- 모임은 하나뿐이며 다중 모임(워크스페이스) 개념은 범위 밖이다.
- 최초로 가입한 회원이 매니저가 되며(승인 불필요), 추가 매니저 지정과 승인 완료 회원의 탈퇴·강퇴 관리는 후속 기능으로 둔다.
- 거절된 사용자의 재신청은 이 기능의 범위 밖이다. 승인 대기 중 알림(푸시)은 제공하지 않으며 사용자가 다시 접속해 확인한다.
- 라운딩 등록·참석 투표·조편성·스코어·핸디캡·랭킹은 후속 스펙이며, 이 기능의 홈에서는 라운딩 데이터가 있으면 표시만 한다.
- 별도 디자인 시안이 없으므로 모바일 우선의 단순한 기본 레이아웃을 사용한다.
- 공지는 텍스트만 지원하며 이미지 첨부와 푸시 알림은 범위 밖이다.
- 날짜와 시각은 한국 표준시(KST) 기준으로 표시한다.
- 서비스는 무료 호스팅 한도 내에서 운영되며 사용자는 안정적인 인터넷 연결을 가진 것으로 가정한다.

## 개정 이력

- **2026-10-27**: 홈 대시보드(US2: 다음 라운딩+최신 공지 카드)는 003의 탭 네비게이션(공지사항/스크린/필드)으로 **대체되어 폐기**. 홈(`/`)은 공지사항 목록으로 이동한다. FR-004와 닉네임 Edge Case를 003 US4(이름 입력/수정)에 맞춰 개정.
